Реализовать автоматическое создание конфигурации **VLESS + xhttp + TLS** за CDN (Cloudflare) в «одно нажатие» при выборе установки с доменом. Трафик должен проходить через Nginx (реверс-прокси) и передаваться в Xray через Unix-сокет.

### 1. Изменение логики протоколов (Функция `generate_xray_config`)

При использовании домена (`HAS_DOMAIN=true`) и выборе селф-хост режима (`REAL_TYPE == 2`):

* **Удаление лишнего:** Исключить из генерации блок `inbound` для прямого порта `$XHTTP_PORT` (VLESS xhttp Reality). Это нужно, чтобы не дублировать протокол и не открывать лишние порты.
* **Сохранение TCP:** Блок `VLESS TCP + Reality (Vision)` на 443 порту (или стандартном порту Reality) **должен остаться** как резервный канал.
* **Добавление Socket Inbound:** Добавить в массив `inbounds` новый входящий поток:
  * **Protocol:** `vless`.
  * **Listen:** `/dev/shm/xray.sock` (Unix-сокет в оперативной памяти).
  * **StreamSettings:**
    * `network`: `xhttp`.
    * `xhttpSettings`: `mode`: `packet-up`, `path`: `$NGINX_WS_PATH` (секретный путь).

### 2. Гибкая настройка SSL (Функция `install_core`)

При настройке домена добавить выбор метода получения сертификатов:

* **Вариант 1: Certbot (Let's Encrypt)** — автоматическое получение через стандартные процедуры.
* **Вариант 2: Cloudflare Origin Certificate (Рекомендуется)** — скрипт запрашивает у пользователя ввод текста сертификата и ключа вручную.
* **Реализация:** Независимо от выбора, сертификаты должны сохраняться по пути:
  * `/etc/letsencrypt/live/$DOMAIN/fullchain.pem`
  * `/etc/letsencrypt/live/$DOMAIN/privkey.pem`
    Это обеспечит единый конфиг Nginx для обоих случаев.

### 3. Настройка Nginx (Реверс-прокси)

Автоматизировать настройку Nginx для приема трафика от Cloudflare:

* **Порт:** Использовать `443` или `2053` (порты, поддерживаемые CF Proxy).
* **Конфигурация Location:** В блоке `server` создать `location` для пути `$NGINX_WS_PATH`.
* **Проксирование:**
  * `proxy_pass http://unix:/dev/shm/xray.sock;`
  * **Обязательные заголовки:**
    * `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;` (чтобы Xray видел реальные IP).
    * `proxy_set_header Host $host;`
    * Поддержка HTTP/1.1 и апгрейд соединения (`Upgrade`, `Connection`).
* **Права доступа:** После создания сокета скрипт должен убедиться, что у пользователя `www-data` (Nginx) есть права на запись/чтение этого сокета.

### 4. Генерация ссылок (Функция `generate_user_pages` / `manage_users`)

Добавить генерацию **третьей ссылки** специально для работы через CDN:

* **Название:** `VLESS XHTTP (CDN/Cloudflare)`.
* **Формат:** `vless://UUID@DOMAIN:2053?type=xhttp&security=tls&sni=DOMAIN&path=PATH&host=DOMAIN#Name-CDN`.
* **Отображение:** Ссылка должна выводиться как в консоли админа, так и на персональной веб-странице пользователя.
